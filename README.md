# 影棋 · YehuStyleGo

Windows 本地围棋软件：从已登录的野狐客户端导出自己的棋谱（默认最近 100 盘，可在设置中提高到最多 1000 盘），学习个人落子偏好，在本软件中与“初步模仿自己”的陪练对弈。棋谱、分析缓存和棋风模型均保存在本机；另可通过房主或自建服务器与朋友联机，联机账号独立于野狐，对局只发送到你选择的联机服务器。

## 启动

- **免安装版**：双击桌面上的 `启动影棋.lnk`，或项目中的 `dist/YehuStyleGo.exe`。直接启动 EXE 不会弹出黑色命令行窗口；分享包内可使用无黑框的 `程序/启动影棋.vbs`。
- **源码版**：双击 `run.bat`，需要 Python 3.12+，无需安装第三方运行依赖。

首次启动需在“设置”填写你自己的野狐用户名；数据位于 `%LOCALAPPDATA%\YehuStyleGo`，与程序目录分开；替换 EXE 不会清空棋谱或模型。

## 界面与主题

右上角的 **“夜间模式 / 日间模式”** 可以即时切换整套界面：

- 日间是暖纸色 + 深玉绿；夜间是深墨色 + 浅玉绿。
- 切换会同步刷新棋盘、胜率图、设置页、试下窗口和终局窗口，并尽量同步 Windows 标题栏颜色。
- 选择保存在本机设置中，下次启动自动恢复。
- 两种主题共用同一套布局和功能，不改变棋谱、模型或分析缓存。

## 自动同步野狐棋谱

1. 自己登录野狐官方 Windows 客户端。
2. 打开 **“棋谱欣赏 → 我的棋谱”**，使列表按最新对局在前排列，并载入足够的历史记录。关闭已打开的历史复盘棋盘和保存对话框，保留列表。
3. 在“设置”选择 **同步/训练盘数上限**（100、300、500 或 1000，默认 100）。同步、棋谱列表和训练使用同一个上限。
4. 在影棋“棋谱库”点击 **“同步野狐棋谱”**，核对账号和保存目录后确认。
5. 同步期间不要操作野狐窗口。影棋会逐盘打开历史棋谱、保存 SGF、验证本人和手数，并只关闭本次打开的历史复盘窗口。
6. 导出后自动去重导入，再使用当前上限内的最近棋谱重新训练棋风。之后可到“模拟对弈”开始本地陪练。

默认原始棋谱目录：

```text
%USERPROFILE%\Documents\YehuStyleGo\FoxRecords\<棋谱编号>\record.sgf
```

已有文件会验证后复用，不覆盖。取消或失败时已经导出的文件保留，修正窗口状态后可重试。客户端版本、主题、缩放或窗口布局改变时，保存按钮的外观校验可能拒绝继续；软件会停止，而不是猜测点击。

同步依赖已经打开的客户端历史列表，**不是后台网页 API 抓取，也不会自动登录**。上限只是请求值：野狐列表实际载入多少盘，最多就同步多少盘；盘数越多耗时越长（1000 盘同步和后续 KataGo 分析可能需要数小时）。可随时取消，已完成的部分会保留。不会操作在线棋局、在野狐自动落子或修改账号设置。

## 导入、复盘与分析

也可使用“导入 SGF”或“扫描文件夹”。支持 UTF-8、GB18030、常见 Big5，以及带 BOM 的 UTF-16/UTF-32 编码；只读原文件，不移动、修改或删除。文件夹增量扫描可在设置中开启，默认关闭，每 30 秒检查一次。

- 按对局日期选取设置上限内最近的**包含本人账号**的棋谱（默认 100 盘，最多 1000 盘）；同一天的野狐棋谱再按棋谱编号排序，避免导入顺序颠倒实际先后。
- 使用内容 SHA-256 去重，没有本人账号的棋谱不参与本人模型训练。
- 双击棋谱逐手复盘。让子摆放与实战落子分开处理，不将让子计作训练样本。
- “训练棋风”可手动更新模型。
- KataGo 配置完成后，点击“分析选中”或 **“分析列表”** 获取真实胜率、近似目差损失和建议变化；复盘页右上角的 **“分析这盘棋”** 可直接分析当前选中的棋谱，已分析过的对局显示“重新分析”。
- 分析完成一盘就缓存一盘，取消后保留已完成部分；下次批量分析会复用当前配置下的缓存。批量分析完成后会同时更新棋力匹配档案。
- 选中分析表中的一手，会先在棋盘上标出 KataGo 首选。点击绿圈或 **“查看推荐变化”** 后，棋盘会像 KataGo/Lizzie 复盘一样显示前排候选点：编号 1–5，圈内同时显示胜率，颜色按较一选损失递增（绿=一选、青=接近、橙=小失、红=较大损失），右侧按同样颜色列出每个候选的胜率、目差、损失和访问数。
- 把鼠标停在某个候选编号上，会在棋盘上直接预览它的推荐变化（淡色编号棋子），右侧对应的候选行同步高亮；移开即消失，不改变当前局面。
- 点击编号、按数字键 **1–5**，或点击右侧变化列表中的任意一行，即可进入该变化。变化手顺在右侧以可点击列表显示，当前手高亮，下一手以淡色棋子提示；用 **← / →**、鼠标滚轮、**Home / End** 或棋盘下方的 **“变化上一手 / 变化下一手”** 逐手查看。红圈标出实战落点，绿圈标出所选候选。
- 进入变化后可以点 **“分析此变化”**，只对这条分支跑 KataGo（起点＋变化每一手，按设置中的访问次数）。完成后手顺列表会显示每一手的本人胜率、目差和「较上步」升降，颜色表示对本人形势的影响（绿=变好、橙=小降、红=明显变差）；结果按引擎配置缓存在内存中，切走再回来会复用。它不会改写整盘分析缓存或棋力档案。
- 按 **Esc** 或点 **“返回实战”** 恢复实战局面；变化只供复盘参考，不会写回棋谱。
- 棋谱列表支持多选。**“删除选中”** 删除选中的棋谱记录及对应分析缓存；**“清空棋谱”** 删除整个棋谱库及全部分析缓存，并关闭自动扫描、清除原棋谱文件夹设置，避免旧 SGF 在下次启动时被重新导入。两者都**不会删除原始 SGF 文件**；清空时会询问是否同时删除本机所有棋风模型和棋力档案，适合把电脑交接给下一位使用者后，让他用自己的棋谱重新训练。

### 对弈中形势与终局

“模拟对弈”新增两个按钮，右栏内容较多时可使用旁边的滚动条：

- **形势判断（KataGo）**：不代你落子，单独分析当前盘面。显示本人和黑白双方胜率、预计领先/落后目数，以及高置信度区域归属数量（含棋子，不等于最终围空）。按本人执色转换视角，目差已含贴目，至少搜索 400 次。结果同时显示在提示窗口和右栏；后续落子或悔棋会清除旧估计。即使用轻量陪练也可单独调用形势判断，但必须先配置 KataGo。
- **终局判定**：双方连续停一手后自动打开，也可以手动点击并确认提前结束。在棋盘上点击整块死子标记为 ×，再次点击撤销，或清除全部标记。程序按移除这些死子后的中国数子规则计分：活子＋己方围空，白方再加 7.5 目；提子不另加分，共用边界的空点为中立。
- 点击 **“确认死子并判定胜负”** 才写入确定结果；关闭窗口只是暂缓，保存时不会将预览当成胜负。有争议可 **“返回继续下棋”**，撤回末尾两次停一手后继续。认输结果不会被数子覆盖。
- 确认后保存 SGF 会包含 `RE[B+…]` / `RE[W+…]` / `RE[0]`、计分说明和标记；原实战落子不被删除。未保存的终局结果在退出时有提醒。

**形势判断不是终局裁决**，引擎胜率也不是你与陪练实际胜率的测量值。终局数子依赖你确认死活；软件不自动求解所有死活、劫争和长生。局面没有收完或死活仍有争议时应继续下棋，而不是把预览数字当成可靠终局结论。

### 独立试下 / 变化推演

在“模拟对弈”中点击 **“试下 / 变化推演”**，会从当前正式局面复制一个独立棋盘：

- 默认从当前轮到的一方开始，黑白自动交替；也可手动指定黑棋或白棋，由你替双方试下，不自动启动陪练。
- 可悔棋、重做、停一手、重置；试下落子从 1 编号，并显示独立的变化手顺。悔棋不会撤回实战落子，另下新变化会替换被撤回的试下后续。
- 完整保留起点的提子、行棋方和劫历史，不能用试下绕过立即回提限制。
- 窗口不是模态对话框：实战及对手思考可以继续，但试下不会自动跟随实战。点击 **“取最新实战局面”** 可主动更新起点，已有变化会先询问是否丢弃。
- **试下不会写回实战，也不会污染正式 SGF、胜负、形势估计或棋风模型。** 关闭窗口直接返回正式对局，临时变化不保存。

### 对局结束后的保存、复盘与棋风更新

在“模拟对弈 → 保存与状态”中：

- 点 **“保存并复盘”**：把当前本地对局保存到数据目录下的 `local-games` 文件夹，自动导入棋谱库、选中该局并打开“复盘分析”。无需再去文件对话框选路径。
- 点 **“导出 SGF 文件…”**：仍可把棋谱另存到你选择的位置，用于分享或备份，不会自动加入棋谱库。
- 保存后的本地对局默认使用你的账号作为本人一方、`影棋-<账号>` 作为陪练一方；它会计入“最近 N 盘”的棋谱列表，因此可以继续做 KataGo 分析、查看胜率曲线和推荐变化。
- 在复盘页点 **“更新棋风”**：用当前棋谱库重新训练棋风模型，训练完成后右下角会提示新的盘数和手数。也可以到“我的棋风”点“重新训练棋风模型”。
- 训练只学习**你本人**的落子；陪练的落子只用于重现局面，不会作为你的棋风样本。新棋谱导入后，模型会显示“棋谱库已更新，当前模型尚未重新训练”，直到你完成一次训练。

本地对局不会在终局确认时自动落盘；需要你在结束时点一次“保存并复盘”。“导出 SGF 文件…”和“保存并复盘”都不会改写原对局。


### 名手棋风陪练

“模拟对弈 → 对弈风格”可以选择 **“我的棋风”** 或已经导入的名手模型：

- 点 **“导入名手…”**，输入名手姓名，再选择装有该名手 SGF 的文件夹。姓名必须与 SGF 的 `PB` 或 `PW` 完全一致；软件会筛出包含该姓名的棋谱，训练并保存一个独立的名手模型。
- 点 **“批量导入多个名手…”**，可以一次输入多个姓名（用逗号或顿号分隔），软件只读取一遍文件夹，然后依次训练所有名手；训练线程使用低优先级，不会把前台的鼠标、浏览器或其他程序抢到卡顿，底部仍可取消。
- 软件**不会自动下载职业棋谱**，也不会附带真实职业棋手的棋谱数据。请只导入你有权使用的 SGF；名手模型只保存在本机数据目录，不会随分享包分发。
- 对弈时选择该名手即可。名手模式使用 KataGo 候选着，再用该名手的落子偏好在候选中选点；默认选点强度为 0.82，可以用滑条调整。它不会使用你的个人棋力损失档案，也不会自动复制该棋手的全部判断或真实段位。
- 没有配置 KataGo 时仍可体验“轻量名手风格”，但强度有限，不能作为真实职业棋力；不要把它当作官方授权或真实棋手本人。
- **“删除当前名手模型”**只删除本机模型文件，不删除原始 SGF。清空棋谱并选择同时清理棋风数据时，也会一并删除名手模型和名手索引。

### 棋力匹配

“模拟对弈”默认勾选 **“棋力匹配：按你的实战损失分布限制选点”**。它使用当前引擎配置下已缓存的批量分析，统计你本人每一手的近似损失，得到中位数、平均数和 5%–99% 分位，并保存为 `strength-profile.json`：

- 陪练每次落子会从你的损失分布中抽取一个目标损失水平，优先在接近该水平的 KataGo 候选着中按个人偏好选点；候选损失不连续时，改按候选损失排序的同一分位选择。因此它会主动走到接近你常见失误程度的棋，而不是永远走引擎最佳着。
- **选点强度**滑条：0.5 按你的实战损失分布选点，越高越接近引擎最佳着，越低允许更大的失误。它不是段位标定，也不保证和真人下出同样的棋。
- 至少需要 **30 手**本人已被分析的落子才会启用；档案缺失或引擎配置改变时，会退回按引擎 `order` 排名选点，并在右栏说明。
- 档案只读取本机缓存，不会重新启动引擎，也不会改写棋谱、胜负或棋风模型。重新批量分析后会刷新档案。

棋力匹配是统计近似：它复现的是你在这批对局中的**损失水平**，不是你的全部判断、战斗力和心理状态。1000 盘也不保证完全一致。用现有缓存抽样回放时，0.5 档的平均候选损失约 2.7 目/手，与同一批数据中 90 手本人落子的约 2.6 目/手接近；这是同批数据的描述性检查，不是独立验证。

### 联机对弈（第一版）

“联机对弈”是独立账号体系，不连接野狐。每个玩家需要注册用户名和密码，服务端生成一个 **9 位数字 UID**；UID 在同一个服务器内唯一，不同服务器之间的账号体系相互独立。服务端只保存加盐 PBKDF2 密码哈希，不保存明文密码，也没有邮箱或密码找回功能。

有两种部署方式：

1. **房主联机**：一个玩家在“联机对弈”点 **“本机开房（启动服务器）”**，程序会在本机启动服务端并显示局域网地址（例如 `192.168.1.5:8765`）。同一 Wi-Fi 下的朋友在“服务器地址”填入这个地址，注册/登录后输入房主分享的 6 位房间码即可。关闭影棋或点“停止本机服务器”后服务停止；公网联机需要端口映射或内网穿透。
2. **中央服务器**：在一台大家都连得到的电脑或服务器上运行 `YehuStyleGoServer.exe`。默认监听 `0.0.0.0:8765`，可用 `--host`、`--port`、`--db` 修改。玩家在客户端填服务器地址，账号和 UID 统一保存在服务端。服务器重启后账号保留，但未结束的房间和对局会丢失。

对局规则：

- 支持 9/13/19 路、中国规则、白贴 7.5 目；服务端校验行棋方、占位、自杀和简单劫。
- 支持停一手、认输、离开房间；对手断开后会显示“已断开，等待重连”，重新登录可回到原房间。
- 双方连续停一手后进入数子确认：服务端按当前盘面计算中国数子结果，双方都点“同意数子结果”才结束；任一方点“继续下棋”会撤回最后两次停一手。**首版不会自动标记死子**，不认可结果时请继续下棋把死子提掉，或重新确认。
- 首版暂不支持聊天、计时、悔棋、观战、等级分和自动死活判定。

**安全边界**：服务器是明文 TCP，没有内置 TLS。请只在可信局域网、VPN 或 SSH 隧道中使用，不要把端口直接暴露到公网；不要复用重要密码。房主启动服务器时 Windows 防火墙可能询问是否允许访问网络。联机账号和野狐账号完全独立，程序不会读取野狐密码或登录信息。

## KataGo 配置

官方来源：

- 引擎：<https://github.com/lightvector/KataGo/releases>
- 网络模型：<https://katagotraining.org/>
- 分析协议：<https://github.com/lightvector/KataGo/blob/master/docs/Analysis_Engine.md>

本机已配置官方 **KataGo 1.18.1 OpenCL + b18c384 模型**，位于 `%LOCALAPPDATA%\YehuStyleGo\engines\official-opencl-1.18.1` 的独立子目录。设置已保存对应路径，无需再次选择。OpenCL 同样使用 RTX 4060 Laptop GPU，避免另行安装 CUDA/cuDNN 运行库。

引擎 ZIP 的 SHA-256 已与官方 GitHub 发布摘要核对。模型来自官方媒体域名，下载摘要记录在 `setup-manifest.json` 中；没有将该记录宣称为独立官方摘要验证。

换机时需从可信官方来源配置引擎与 `.bin.gz` 模型，并在“设置”中保存、测试。程序将所有评估固定为黑方视角，再转换为本人视角，避免执白时胜率和损失反转。日志和配置位于数据目录中的 `engine-work`。

默认每局面 120 次访问，最多 4 个局面并行，适合初步复盘，不是最终裁定。损失是相邻局面搜索估值的差，受浅搜索误差影响。缓存按可执行文件、模型路径/大小/修改时间、访问次数和引擎配置区分，旧配置的缓存不会伪装成新配置结果。

首次 OpenCL 调优可能较慢。当前每次引擎陪练回合重新创建进程，存在模型加载开销；不启用 KataGo 时会明确使用轻量启发式陪练，不显示伪造胜率。

## 棋风模型的边界

这不是从零训练完整围棋神经网络，也不是微调 KataGo。模型学习：

- 布局、中盘、后半盘分别的落子特征权重；
- 一到五线、星位/三三/小目、与上一手距离、贴靠、连接、局部疏密、提子和救棋特征；
- 个人落子位置频率及局部 3×3 模式。

训练使用本人真实落子和采样合法候选手进行成对逻辑排序，对手落子仅用于重现局面，不作为正例。启用 KataGo 时，陪练从引擎候选中选点：开启棋力匹配时按你实战损失的允许误差带筛选，再按个人偏好取舍；不使用匹配档案时按引擎 `order` 排名筛选。不会为了“模仿”去下引擎认定明显不利的棋；不启用引擎时才使用轻量启发式陪练。

**已完成 100 盘训练不代表已经证明“像本人”。** 当前没有跨对局留出验证，不显示虚构的模仿准确率。模仿程度和选点强度滑条不是野狐段位标定；增加训练盘数、开启棋力匹配也不保证复现全部判断和失误。9/13/19 路共用特征模型，小棋盘模仿效果需另行验证。

本地棋盘禁止占位、自杀和立即回提。中国规则棋谱与 KataGo 的 `chinese` 预设均使用简单劫规则，允许不属于立即回提的旧局面重复；仍保留显式位置全局同形模式。它不是完整赛事裁判，不处理长生等特殊终局判定，也不完整复现所有其他规则。

SGF 只使用第一个变例作为主线；支持首手前分节点的 AB/AW/AE/PL。实战中途摆子编辑、非围棋记录和非正方形棋盘会明确拒绝，不静默误读。

## 隐私与同步边界

- 野狐同步流程不收集野狐密码、Cookie 或登录令牌。
- 联机账号由你选择的服务器保存用户名、UID 和加盐密码哈希；客户端不保存密码。联机落子会发送到该服务器，本地棋谱、模型和分析缓存不会上传。
- 不读取野狐客户端进程内存、不注入、不拦截野狐登录或网络协议。
- 使用标准 Windows 控件消息和目标窗口内的保存按钮外观校验，不移动全局鼠标。
- 每次操作核对目标窗口所属的 `foxwq.exe` 进程；未知窗口、异常状态和外观不符时停止。
- 不绕过验证码、安全机制或客户端执行策略。
- 本地模型、原始 SGF、SQLite 缓存及个人窗口截图均不应作为源码提交或分享。

尚无本项目已验证可用的官方匿名历史 API。OpenFoxWQ 接口需要密钥和账号认证，本版没有接入，也没有复用其他用户身份。参考：<https://github.com/openfoxwq/api>、<https://edu.foxwq.com/complex/useragreement.html>。
